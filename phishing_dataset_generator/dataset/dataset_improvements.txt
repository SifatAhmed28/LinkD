### But removing features isn't the real fix

The better solution is to fix the **dataset generator**.

Those are actually legitimate phishing-detection features in the real world. Domain mismatch is useful. Form actions are useful. Password fields are useful.

The problem is that your synthetic generator currently defines them too cleanly.

You want overlap.

For example, `has_password_field` should look more like:

```text
                Legitimate    Phishing

False              40%          15%
True               60%          85%
```

not:

```text
                Legitimate    Phishing

False              56%           0%
True               44%         100%
```

Similarly, `form_action_type` should have overlapping distributions.

Something healthier might be:

```text
                               Legit     Phish

same_origin                     55%       20%
relative                        20%       15%
empty                            5%        8%
javascript                       3%        7%
official_brand_cross_origin     10%        5%
same_platform_cross_origin       5%       25%
external_cross_origin            2%       20%
```

Not necessarily those exact percentages, but the key is:

> No category should automatically determine the label.

Your synthetic legitimate third-party pages are also causing this interesting result:

```text
page_brand_domain_mismatch=True
```

for about half of legitimate pages, which is actually good for reducing leakage.

But phishing pages are still:

```text
page_brand_domain_mismatch=True = 100%
```

So there is still a one-way rule:

```text
False -> definitely legitimate
```

You could generate some phishing pages where the apparent page hostname is the official domain in a controlled synthetic setting, or simply avoid using that generator-ground-truth feature as a model input.

The biggest issue remains `form_action_brand_domain_mismatch`:

```text
legitimate = always False
phishing   = always True
```

That one should absolutely be excluded **until you modify generation logic**.

### Your TLD score also needs examination

This:

```text
label 0 mean = 0.009
label 1 mean = 0.156
```

may be partly caused by your attacker-owned phishing domain generation.

Especially if unknown TLDs currently do this:

```python
return TLD_RISK.get(
    tld,
    MAX_TLD_RISK
)
```

then unknown attacker TLDs become:

```text
risk = 1.0
```

That can create artificial separation.

I'd much rather use something like:

```python
DEFAULT_TLD_RISK = 0.0
```

or perhaps the median observed risk:

```python
DEFAULT_TLD_RISK = np.median(ATTACKER_TLD_WEIGHTS)
```

depending on what "unknown" means in your data.

`unknown TLD == maximum phishing risk` is a pretty aggressive assumption for ML training.
